# 企业微信微盘知识库同步方案

> 决策日期：2026-09-17
> 状态：方案已确定；跨身份拉取已验证通过，进入完整开发。

## 1. 背景与问题

企业微信微盘 API 不能作为企业既有人工创建共享空间的完整采集通道；而 `wecom-cli` 虽可按已知文件标识下载离线文件、读取部分在线文档，却不能按指定文件夹列举子项或递归构建目录树。

因此，不能仅依赖企业微信 API 或 CLI 实现“将某一项目文件夹完整同步到 WeKnora 知识库”。相关 CLI 能力边界见[企业微信微盘 CLI 目录枚举调研](./企业微信微盘CLI目录枚举调研.md)。

## 2. 采用方案

采用“项目端 RPA 目录发现 + 服务端 CLI 内容拉取 + WeKnora 统一入库”的分层同步方案。

```text
各项目负责人电脑
  RPA：扫描获授权的项目微盘目录，仅上报目录清单
        |
        v
WeKnora 服务端
  清单存储、范围校验、变更检测、拉取任务与同步审计
        |
        v
服务端专用资料管理员 CLI
  按已发现的文件标识下载离线文件，或读取支持的在线文档正文
        |
        v
WeKnora 知识库
  文件解析、切分、索引、检索与问答
```

### 2.1 项目负责人本地 RPA 的职责

- 以项目负责人已有的企业微信访问权限进入指定共享空间和项目根目录。
- 在 Agent 打开的微盘浏览器中进入要同步的文件夹，然后在 WeKnora 页面点击“读取 Agent 当前文件夹”并提交同步申请。目录页面地址只作为 Agent 与服务端之间的内部定位信息，默认不要求负责人识别或手工输入；负责人只能提出同步范围，不能自行决定入库。
- 递归扫描目录树，只采集并上传元数据，不下载项目文件内容。
- 上报文件/文件夹标识、父节点标识、共享空间标识、完整路径、类型、修改时间、大小；在线文档还应携带文档标识或可供 CLI 读取的链接。
- 周期性执行以实现准实时同步；RPA 受客户端更新、登录过期、锁屏和权限弹窗影响，不承诺严格实时。

### 2.2 WeKnora 服务端的职责

- 接收负责人提交的同步申请，展示为“待审批同步源”。服务端管理员核对目录根链接后，选择目标团队空间/知识库并批准、暂停或撤销同步；未获批准的申请不得创建内容拉取任务。
- 为每个已批准同步源配置允许同步的共享空间、根目录和目标知识库。负责人提交的目录链接应由管理员确认后直接采用，不要求管理员再次手工粘贴同一个链接，以减少重复录入和链接错配。
- 接收并保存项目端目录清单，拒绝超出该项目允许范围的条目。
- 以“共享空间标识 + 文件标识”作为来源主键；用修改时间、大小和必要时的内容哈希识别新增、更新和删除。
- 仅对新增或变更的条目创建内容拉取任务，并记录成功、失败、跳过和待人工处理原因。
- 内容完成入库后清理服务端临时下载文件；知识库原始文件和索引所需的持久化存储仍按 WeKnora 的存储策略保留。

### 2.3 服务端资料管理员 CLI 的职责

- 使用一个经企业确认、可访问所有纳入同步范围项目资料的专用资料管理员授权上下文运行。
- 对 RPA 已发现的离线文件按文件标识下载，并将内容交给 WeKnora 解析流程。
- 对支持读取正文的在线 Word、表格、智能表格、智能文档等类型，调用对应 CLI 能力读取正文后入库。
- 对当前 CLI 无正文读取能力的在线 PPT、收集表、思维导图、流程图、汇报等类型，记录为“不支持”，不伪造成功状态。
- 以受并发、速率、单文件大小和临时目录容量限制的同步任务执行，不把全量项目文件长期同步到服务器磁盘。

> WeKnora 已配置的企业微信 IM Bot ID / Secret 只用于聊天机器人 WebSocket 通道，不能直接视为微盘资料管理员的访问授权。服务端运行 CLI 时必须使用经验证的 CLI 授权上下文。

### 2.4 同步申请与审批流程

```text
项目负责人本地 RPA 工具
  在 Agent 浏览器进入目标文件夹，由页面读取后提交同步申请
        |
        v
WeKnora 服务端：待审批同步源
  管理员核对目录，绑定团队空间与目标知识库，批准或拒绝
        |
        v
已启用同步源
  RPA 持续上报该目录范围内的清单；服务端按变更创建拉取任务
        |
        v
资料管理员 CLI 拉取内容，直接入库到绑定知识库
```

同步源应具备以下配置与状态：

| 配置/状态 | 说明 |
|---|---|
| 项目/团队、负责人、RPA 设备 | 记录同步申请来源及可追溯责任人 |
| 目录根链接和稳定标识 | 表示服务端已批准的唯一同步范围 |
| 目标团队空间、目标知识库 | 由服务端管理员决定；内容直接入库，不先进入泛用共享空间 |
| 路径边界、文件类型、同步频率 | 限制可采集范围与任务调度 |
| 待审批 / 已启用 / 已暂停 / 已撤销 | 控制同步源的生命周期 |

服务端必须将 RPA 上报的每个条目与已批准根目录做范围校验。即使本地工具上报其他文件标识，或负责人能在企业微信中访问更多内容，服务端也不得为这些未批准范围内的条目创建资料管理员 CLI 拉取任务。

### 2.5 服务端逐项拉取与入库

服务端的 `wecom_cli` 数据源应实现与现有数据源一致的文件级流式同步：由同步任务消费项目端 RPA 上报的增量清单，而不是由 CLI 枚举目录。每成功处理一项后持久化进度，任务中断后从最后一个安全游标恢复。

```text
项目端 RPA Sync Agent
  上报已批准目录的增量清单
        |
        v
服务端 wecom_cli 同步任务（FetchStream）
  逐条读取变更记录
  → 校验条目是否位于已批准根目录
  → 按类型分流：CLI 下载离线文件，或读取支持的在线文档正文
  → 立即交给解析、切分与知识库入库
  → 持久化游标、文件状态和失败原因
  → 删除该条目的临时下载文件
        |
        v
继续下一条
```

该模型是“文件级流式”，其目标是避免整个项目目录在内存或本地磁盘中累积：任意时刻只处理受并发数限制的少量文件。它不是“端到端字节流”。当前 `wecom-cli` 下载接口会产生本地 `file_path`，因此离线文件需短暂落在服务端临时目录，完成解析/入库后立即删除。

若未来需要“网络字节直接送入解析器、不经临时文件”，需另行改造数据源 `FetchedItem` 与解析链路以支持 `io.Reader` 或分块上传；这属于第二阶段优化，不阻塞本方案实施。

## 3. 方案收益

- 项目负责人电脑只传输轻量目录信息，不需要下载和保存完整项目资料，避免客户端磁盘被大批文件占用。
- 文件下载、解析和入库集中在服务端，便于统一限流、重试、审计、存储策略和故障排查。
- 项目权限仍由企业微信的既有共享空间权限约束；各项目 RPA 仅发现本账号可见的目录。
- 服务端可按项目与知识库建立明确映射，避免资料混入错误知识库。

## 4. 跨身份拉取验证结论

此前的唯一阻塞性验证项为：

> 负责人端 RPA 采集到的文件标识，能否被服务端资料管理员的 CLI 用同一标识读取和下载；并分别验证普通文件、在线文档、无权限文件和已删除文件。

当前状态：**已由项目方验证通过**。负责人端 RPA 发现的内容引用能够由服务端资料管理员 CLI 跨身份消费，因此不再阻塞开发。该结论仍须通过受控环境集成测试固化，防止 `wecom-cli` 升级后回归。

建议测试矩阵：

| 回归场景 | 负责人端 RPA 预期 | 服务端 CLI 预期 | 验收标准 |
|---|---|---|---|
| 普通离线文件 | 发现并上报标识与元数据 | 下载成功 | 内容可解析并入库 |
| 支持的在线文档 | 发现并上报文档标识/链接 | 正文读取成功 | 内容可转换并入库 |
| 资料管理员无权限的文件 | 可由负责人发现 | 读取或下载失败 | 明确记录“服务端无权限”，不入库 |
| 源端已删除文件 | 清单不再包含或标记删除 | 读取或下载失败 | 现有知识库记录按删除策略处理 |

## 5. 实施前提与约束

- RPA 本地代理必须以项目负责人明确授权运行，并通过设备注册令牌与 WeKnora 服务端建立可信关联。
- 服务端必须对上传清单进行项目范围校验，不能把客户端提交的任意文件标识直接作为可下载目标。
- 需要为服务端 CLI 配置并发、速率、重试和临时文件磁盘上限，避免拉取任务挤占业务服务资源。
- 若企业微信客户端可为目标目录提供官方本地同步文件夹，应优先评估“本地目录监听”替换 RPA；RPA 作为无法使用官方同步目录时的兼容目录发现层。
- 若未来版本的跨身份拉取回归失败，同步源应进入明确的“连接不可用/内容不可消费”状态，不得静默改为负责人电脑下载并上传内容。

## 6. 最终产品与治理决策

### 6.1 入口、权限与凭据归属

- 顶层“RPA 同步”页面负责 Agent 安装与在线状态、企业微信扫码登录、设备管理、同步申请和扫描故障；知识库设置中的“数据源”负责已绑定同步源的连接选择、策略、运行记录和启停。两处展示同一个同步源，不复制配置。
- 同步申请以“读取 Agent 当前文件夹”为主流程：负责人在 Agent 浏览器里进入目标文件夹，Agent 将当前文件夹标题与内部目录页面地址返回给 WeKnora。当前微盘页面可能为旧版 `#/webdisk/...`，也可能为新版 `/webdisk/index#/cgi/ssr/space/...?...folderid=...`；普通用户无需理解或手工复制该地址，页面只在高级排障区域允许手工填写。它不是离线文件下载使用的 `https://drive.weixin.qq.com/s?k=...` 分享链接；服务端和 Agent 都必须拒绝把分享链接当作同步根目录。
- `Contributor` 及以上可以为自己有编辑权的知识库提交申请；`Admin / Owner` 批准并绑定目标知识库。`Admin / Owner` 直接创建时视为隐式批准，但仍须等待首次完整清单。
- `BotID / Secret` 属于租户级、可复用的“企业微信 CLI 连接”，而非知识库配置副本。租户可创建多个命名连接并选择默认连接；一个连接可供多个同步源引用，轮换凭据后统一生效。
- 只有 `Owner` 可以创建、轮换或删除连接凭据；`Admin` 可以选择现有连接，`Contributor` 不可见凭据。Secret 加密保存且永不明文回显，异步任务只携带连接 ID。

### 6.2 Agent 运行与通信

- Agent 是 Windows 每用户程序，首次从“RPA 同步”页面下载安装并使用一次性注册码绑定，随后自动转为无黑窗口的后台进程，并在登录后自动启动；不以无法交互桌面的纯 Windows Service 运行。开发环境由 `agents/wedrive-sync/build-windows.ps1` 生成单文件包并由 Vite 提供下载；生产环境必须改用代码签名的包及可信分发地址。
- Agent 使用独立持久化 Chromium Profile。扫码、异常验证或人工确认时显示浏览器；锁屏、注销或没有可交互桌面时暂停扫描并上报原因。
- Agent 主动建立 TLS WebSocket，不在负责人电脑开放入站端口。服务端只能下发注册、登录、扫描、取消等固定协议指令，不能下发任意脚本。
- 网页扫码所需二维码由 Agent 截取后短暂中转，只保存在服务端内存中且最长约 60 秒；Cookie、Profile 和企业微信登录态不得离开本机。
- 设备通过十分钟有效的一次性注册码注册，在本机生成设备密钥，私钥使用 Windows DPAPI 保护。设备被撤销后立即失去任务与上传权限。

### 6.3 快照、自动分享和删除

- 清单采用“开始快照、分批上传、提交总数与摘要”的原子协议；中断快照保持不完整，不参与差异和删除计算，重复批次必须幂等。
- 同步源批准后才允许创建分享链接。“允许自动分享”默认开启：已有链接直接复用，缺少链接的受支持离线文件由 Agent 创建。
- 自动分享不得用于添加在线文档成员或扩大共享空间权限。分享链接视为访问凭据，加密保存且不得出现在日志、普通页面或错误文本中。
- 不为每条分享链接单独写审计日志，只记录批次汇总数量；审批、启停和自动分享设置变更仍进入审计。
- 启用删除同步时，条目必须连续两次完整快照缺失且经过 24 小时宽限期，才能删除知识库内容。

### 6.4 内容范围与 Worker

- 第一版处理 WeKnora 可解析的离线文件，以及 `wecom-cli` 能稳定导出的在线 Word、表格、智能表格和智能文档。
- 在线文档缺少内容成员权限时明确标记失败，由企业管理员统一授予；RPA 不自动加入成员。其他不支持类型保持可见的“不支持”状态。
- CLI 运行在专用 Fetch Worker 中，Web 主服务只管理连接和任务。Worker 才能在执行时解密凭据，并使用独立临时目录、并发限制、速率重试和崩溃残留清理。

### 6.5 信任边界

服务端校验已注册设备签名、批准根节点、完整父子链和快照摘要，用于防范误操作、传输篡改和普通越权。但服务端无法只凭 RPA 上报从密码学上证明文件真实属于根目录，因此本方案信任公司的受管设备与代码签名 Agent，不覆盖拥有本机管理员权限并主动篡改 Agent 的恶意负责人。若企业要求抵御该威胁，必须引入官方服务端枚举能力或企业终端安全证明。

## 7. 当前实现与本地开发预览

第一版已在 WeKnora 中落地以下纵向链路：

- 左侧“RPA 同步”页面、知识库“数据源”中的企业微信微盘入口、设备注册和浏览器—Agent 控制通道；
- 租户级 CLI 连接、审批后的同步源、签名设备、原子清单快照及数据库迁移；
- RPA Agent 的持久化 Chromium Profile、XHR 清单捕获、递归目录校验和缺失分享链接创建；
- `wecom_drive_rpa` 流式连接器，按离线文件、在线 Word、表格和智能文档分流，逐项检查点、限流重试、临时文件清理及延迟删除；
- 每个 CLI 连接使用独立 `WECOM_CLI_CONFIG_DIR`。Worker 首次使用或 Bot Secret 轮换后，通过 CLI 的非交互凭据初始化入口生成该连接自己的加密 `credentials.enc`，避免误用服务器全局 CLI 登录态。配置根目录由 `WECOM_CLI_STATE_DIR` 指定。

当前 `wecom-cli 1.2.0` 的自动初始化通过隐藏的 `auth init --bot-id/--secret` 参数完成。由于操作系统进程参数在部分宿主机上可能被同机用户观察，生产 Worker 必须运行在独立低权限账号或容器中，并限制宿主机进程查看权限；应用日志不得记录该命令行。若企业无法满足这一隔离要求，应由运维预先初始化每个 `WECOM_CLI_CONFIG_DIR`，或等待 CLI 提供 stdin/文件描述符形式的凭据注入。

Fast Development Mode 下，前端由 Vite 热更新，可以直接刷新 `http://localhost:5173/platform/wedrive-sync` 查看页面；Go 接口、依赖注入和迁移需等待 Air 自动重编译（通常 5–10 秒）。若 `make dev-app` 未检测到 Air，则必须手工重启后端。新增表还要求 `AUTO_MIGRATE=true`，或由开发者手工执行 PostgreSQL `000096` / SQLite `000017` 迁移。Windows Agent 是独立进程，修改其代码后需要单独重启，不会随前后端热更新。

当前仍需在真实企业微信环境完成端到端验收：自动分享 UI 选择器、CLI 限额恢复后的实际下载/在线文档导出、服务器临时目录策略，以及安装包签名和企业终端分发。跨身份下载能力已由项目方验证通过，不再作为研发阻塞项，但必须保留为版本升级回归用例。
