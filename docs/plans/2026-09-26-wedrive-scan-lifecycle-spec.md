# Spec：微盘目录扫描生命周期

状态：设计取舍 Q1–Q8 已确认。日期：2026-09-26。

GitHub Spec：[rudyvv/myWeknora#1](https://github.com/rudyvv/myWeknora/issues/1)。

## 目标

每次目录扫描必须对应一次明确的**目录扫描尝试**。只有当前有效尝试可以上传清单、提交完整清单、上报失败或续租。长扫描可以续租；服务端重启不取消仍有效的尝试。扫描频率、同设备串行、一次十分钟重试、仅手动默认值和内容入库策略沿用 [ADR-0002](../adr/0002-wedrive-per-source-scan-cadence.md)。

本项不改变 RPA 如何遍历微盘、不改变 CLI 内容拉取，也不改变目录清单的删除宽限规则。

## 现状与风险

- `ClaimScan` 将源设为 `running` 并设置固定 30 分钟租约，但领取响应没有扫描尝试身份；本机工具只读取成功布尔值。
- `BeginSnapshot`、`UploadSnapshotItems` 和 `CommitSnapshot` 只验证设备、来源和清单状态，未验证清单属于当前领取。旧尝试的延迟提交可能在新的领取之后清算新尝试。
- `ReportScanFailure` 只验证来源为 `running`。旧尝试的迟到失败可能结束新尝试。
- `RecoverInterruptedScans` 在服务端重启后、工具重连时将此前的 `running` 扫描直接标记失败，即使其租约尚未过期。
- 扫描状态转移分散在领取、失败、完成、批准和频率更新路径中，测试难以从一个稳定 seam 验证所有不变量。

## Module、interface 与 seam

建立内部的**目录扫描生命周期 module**，以当前微盘同步源的扫描字段、当前时间和动作作为输入，统一决定领取、续租、失败、超时、完成以及频率变更后的扫描状态。module 的 interface 包括动作允许条件、状态转移、错误语义和调度规则；不要求导出 Go `interface` 类型。

seam 位于现有 `WeDriveService` 的事务入口与扫描状态转移之间。现有方法保留设备认证、授权、数据库事务和审计职责；生命周期 module 隐藏重试和下次扫描时间的计算。来源审批、知识库激活、清单内容校验继续由原有流程负责。持久化由现有 GORM 实现承担，不为单一生产 adapter 再引入 repository 抽象。

测试主要跨 `WeDriveService` 的公开 interface，使用真实 SQLite/PostgreSQL 验证事务结果；少量内部规则测试只覆盖难以通过事务组合充分观察的时间边界。后续增加状态时，调用方不应重复编排扫描字段。

## 身份与持久化

- 领取成功时由服务端生成不可预测的 `scan_attempt_id`。同一来源每次领取都得到新值；清单编号 `sequence` 不能充当尝试身份。
- `wedrive_sources` 保存当前尝试身份、最后一次已确认进展的序号与时间；`wedrive_snapshots` 保存创建它的尝试身份。两库均增加迁移。来源处于 `running` 时必须有当前尝试身份和租约；退出 `running` 时清除这些运行字段。迁移前已完成的历史清单原样保留，其尝试身份允许为空；新清单必须有身份。
- 每次尝试最多创建一份目录清单。重复 `BeginSnapshot` 请求返回该尝试已存在的清单；根节点和预期条目数不一致时返回冲突。
- 历史 `running` 行没有尝试身份，迁移时转为可重新领取状态：自动源进入重试等待，手动源显示失败且允许重新手动扫描。已完成清单不修改。

## 有签名工具协议

| 操作 | 请求与响应 | 服务端约束 |
| --- | --- | --- |
| 领取 | `POST /sources/:id/claim-scan`，返回 `scan_attempt_id` 与租约截止时间 | 来源可扫、计划已到期、同设备没有其他有效尝试；一次事务内领取 |
| 续租 | 新增 `POST /sources/:id/scan-lease`，请求含 `scan_attempt_id` 与单调增加的 `progress_seq`，返回新截止时间 | 仅当前未过期且满足进展与最长时长限制的尝试可续租 |
| 失败 | 现有 `scan-failure` 请求增加 `scan_attempt_id` | 只有当前未过期尝试可使源进入失败或重试 |
| 开始清单 | `BeginSnapshot` 请求增加 `scan_attempt_id` | 先校验当前尝试，再创建或返回该尝试的上传会话 |
| 上传/提交 | 路径中的 `snapshot_id` 找到所属尝试 | 同一事务内确认该尝试仍是当前且未过期；完整提交原子更新清单与扫描状态 |

所有请求继续受设备签名保护。服务端从请求中的尝试身份与数据库当前身份做匹配，不把客户端自报的时间或扫描状态当作权威。工具仅保存正在执行的尝试身份；失去租约后停止后续上传和提交，并向页面显示安全的失败类别。

当前工具版本为 `0.3.1`；新协议以 `0.4.0` 为最低版本。旧版工具不能领取或提交新协议的扫描。服务端在每个扫描写入入口校验**本次请求**的协议版本及必要字段，返回明确的升级错误；不能只依赖设备记录中的历史版本或来源列表过滤，因为旧工具仍可直接访问已有写入入口。前端按新最低版本提示升级。服务端、新版工具安装包和升级提示按同一发布批次交付。

## 状态与时间规则

| 事件 | 前置条件 | 结果 |
| --- | --- | --- |
| 领取 | 来源可扫；同设备没有其他有效 `running`；计划领取已到期 | `running`，新尝试身份与租约，记录开始时间；手动领取清零旧重试计数 |
| 续租 | 身份匹配，当前为 `running` 且尚未过期 | 延长当前租约；不改变最近成功时间或扫描频率 |
| 完整提交 | 清单完整且有效，身份匹配，租约有效 | 清单 `complete` 与来源成功状态在同一事务提交；清空尝试、租约、重试和错误；仅手动转 `idle`，自动转 `waiting` 且以完成时间加当前频率计算下次到期 |
| 失败/超时 | 当前有效尝试失败，或当前租约已过期 | 清除尝试和租约；自动源首次失败十分钟后重试，第二次按当前频率等待；手动源为可重新领取的 `failed` |
| 运行中修改频率 | 已有有效尝试 | 不取消当前尝试；完成或失败后使用新频率计算后续时间 |

租约在 `now >= scan_lease_expires_at` 时过期。任何写入入口遇到过期的当前尝试，应在事务内完成超时状态转移，再拒绝旧请求；领取入口还应清理同设备已过期尝试，然后判断是否可领取。过期来源无需依赖服务端进程内状态才能重新扫描。服务端重启时不主动取消尚未过期的尝试；工具重连后可以凭同一身份继续续租。

旧尝试的开始清单、上传、未完成清单的提交、失败和续租统一返回冲突，不得改变当前来源或完整清单。唯一例外是**已成功提交**的同一清单：等价的重复提交可返回原结果，即使后来已经开始新尝试，也不得重写来源状态、重算下次扫描时间或重复审计；条目数、摘要或分享统计不一致时返回冲突。并发事务的锁顺序固定为先来源、后清单，避免领取与提交互相等待。

工具每 5 分钟尝试续租，服务端每次最多把租约延至 `now + 30 分钟`，并截断在领取时间后 **4 小时**。只有真实扫描进展才提高 `progress_seq`：已校验的目录列表、首次接纳的条目、分享链接操作完成或清单批次上传完成均可计一次；单纯定时器、重复 UI 文案和未验证的网络响应不算。服务端保存最近一次更高序号的时间；领取后或上次确认进展后满 **20 分钟**仍无更高序号时，拒绝续租并以安全错误码结束该尝试。到达 4 小时上限时也结束尝试；两者都沿用该源既有的失败/重试规则。进展序号和时间仅用于活性判断，不含路径、文件名或链接。这些间隔作为可配置常量，初值须由测试固定。

续租必须先于当前租约到期；网络暂断可以重试，超时后不得复活旧尝试。工具失去续租资格后应停止继续生成或上传清单，并允许该来源按既定规则重新扫描。

## 验收

1. SQLite 与真实 PostgreSQL：同设备并发领取最多成功一个；旧尝试在新领取后不能失败、上传或提交；过期边界及重试时间一致。
2. 清单上传中、完整提交后，以及重复提交时分别重试；只产生一份完整清单及一次成功状态转移、一次审计。
3. 超过原固定 30 分钟的有进展扫描可续租并完成；20 分钟无进展及 4 小时硬上限都能释放扫描名额，失去租约的工具不能提交。
4. 服务端重启后有效尝试可继续；超时尝试可重新领取。仅手动源在重启、连接恢复或页面刷新后不自动扫描。
5. 旧工具收到升级错误且不能改变扫描状态；升级提示指向新工具。迁移前的运行中记录不会永久显示“扫描中”。
6. 运行中修改频率不取消扫描，下一次时间使用新频率；CLI 内容入库不会因目录扫描产生自动任务。
