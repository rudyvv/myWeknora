# 源码同步目录留空选择整个仓库

用户要求源码与文档保持相同的范围语义：留空选择整个仓库，填写路径选择限定范围，两种情况下排除规则均生效。“下一步”继续检查真实接入条件。

## 变更

- 移除源码同步入口和预览流水线检查中的“必须指定目录”限制。沿用已有 Git 清单匹配逻辑，空 paths 选择全仓，排除规则随后应用；无需迁移数据库。
- 前端同步目录取消必填标记，使用“留空选择整个仓库”提示。“下一步”自动检查行为保持不变。
- 保留模型、解析服务、可处理文件格式、文件数量/大小、Git 拉取量、存储与索引限制。资源预算超限提示用户缩小同步目录或增加排除规则。未引入自动跳过坏文件或关闭 QA 的行为。
- 全仓是选择范围的含义，并不保证所有类型文件都能入库；不满足处理条件仍需排除相应文件或调整配置。源码发布与技术 Wiki 独立生成的原有行为继续保留。

## 验证

- 前端 8 个编辑器流程测试与 13 个多语言检查通过，包括目录留空、保留排除规则、超限就地提示、不推进、不保存或触发同步。新全仓测试在改动前确实被旧目录必填校验阻断。
- 使用独立 source_test 数据库、真实 Git 拉取、解析 HTTP 服务和 PostgreSQL 双索引，验证全仓根文件及子目录文件可发布、检索、读取固定提交；被排除二进制文件只保留清单记录，没有源码索引身份。新测试在改动前被后端明确目录限制阻断。
- 验证全仓预算超限不能替换已有 publication，指定目录同步与模型配置错误保留旧版本的既有行为仍通过。
- 前端生产构建通过，有项目既有分包体积提示。
