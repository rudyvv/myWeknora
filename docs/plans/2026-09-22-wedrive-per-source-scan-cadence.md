# 微盘同步源目录扫描频率实施计划

## 目标与边界

为每个 **微盘同步源** 增加独立的目录扫描频率设置：仅手动、每 30 分钟、每小时、每 6 小时、每天。该设置只控制 Windows RPA Agent 生成并提交目录清单，不触发 wecom-cli 下载、解析、向量化或 Wiki 生成。

CLI 内容入库保持手动触发。微盘数据源不登记内容入库 Cron；迁移时清除已有微盘数据源误登记的 `data_sources.sync_schedule`，不影响其他连接器。

## 已确认的产品行为

- 仅手动：Agent 启动、连接恢复、项目启动时均不自动扫描；只能由管理员点击“立即扫描”。
- 自动频率：同步源获批后立即进入待首次扫描状态；Agent 离线时保留该状态，恢复后每源最多补扫一次。
- 正常周期：以下一次完整扫描成功的完成时间为基准，分别等待 30、60、360、1440 分钟。
- 失败周期：计划扫描失败后十分钟重试一次；重试仍失败则回到该源的正常周期。错误必须沿用不含路径、文件名、分享链接或凭据的安全摘要。
- 并发：同一设备任何时刻只能执行一个目录扫描。手动扫描提升已经排队的计划扫描；进行中的扫描不重复启动。
- 分享链接：自动扫描与手动扫描都严格使用该源的 `auto_share` 开关。
- 权限：仅 Admin / Owner 可以设置频率、调整既有源或发起立即扫描。
- 既有源：迁移后默认每 30 分钟，并根据最后完整扫描时间决定是否已到期。
- 新申请：目录扫描默认仅手动；获批后仍由管理员手动发起首次扫描，除非管理员显式选择自动频率。

## 设计

### 1. 持久化模型

在 `wedrive_sources` 增加以下目录扫描专用状态，PostgreSQL 与 SQLite 迁移同步维护：

- `scan_interval_minutes`：非空整数，只允许 `0`、`30`、`60`、`360`、`1440`；`0` 表示仅手动。
- `next_scan_at`：下一次自动扫描可领取的时间；仅手动源为 `NULL`。
- `scan_retry_count`：当前周期已发生的计划扫描失败次数，仅允许 `0` 或 `1`。
- `scan_state`：`idle`、`waiting`、`running`、`retry_wait`、`failed`，供 RPA 页面展示。
- `scan_lease_expires_at`：已领取扫描的租约到期时间，避免 Agent 进程崩溃后永久显示运行中。
- `last_scan_started_at`、`last_scan_error_code`：展示最近执行与安全分类错误；不得存放微盘 URL、文件名、分享链接、Cookie 或 CLI Secret。

继续使用已有的 `last_complete_scan_at` 作为最近成功完整清单的权威时间。成功提交清单时，在同一事务中清空重试状态、更新 `last_complete_scan_at` 和计算 `next_scan_at`。迁移为现有源填入 30 分钟；若已有完整扫描，则下一次时间为该时间加 30 分钟，已经到期的源标记为可领取而不是在迁移 SQL 中直接发起扫描。

### 2. 服务端协议与调度归属

服务端是“是否到期、是否可运行、下次何时运行”的权威方；Agent 只领取自己设备上可执行的源并执行浏览器操作。这样 Agent 重启、WebSocket 重连或打开 RPA 页面都不会重置频率。

新增并测试以下受签名 Agent 保护的协议：

1. `GET /wedrive/agent/sources` 返回扫描频率、下次到期、扫描状态与允许执行的来源信息。
2. Agent 在计划或手动扫描前调用原子“领取扫描”接口。服务端校验设备绑定、源状态、到期时间、租约和同设备串行约束；相同源的手动请求可提升排队任务，运行中的任务返回已运行。
3. Agent 在浏览器启动失败、登录失效、目录列表超时或其他扫描失败时上报安全错误分类。服务端负责十分钟重试及第二次失败后的下一周期计算。
4. 完整快照 `commit` 成功时清算该次领取并安排下一周期。租约过期后，服务端将孤儿 `running` 状态恢复为待领取状态，不伪造成功扫描。

保留当前 WebSocket 的 `scan` 命令，但将其标记为 `manual`；计划扫描不需要页面打开或 WebSocket 浏览器客户端在线。Agent 的 60 秒轮询只查询“当前设备可领取的源”，不再读取进程内 `last_scan` 来判断 30 分钟。

### 3. Agent 行为

- 将固定 `1800` 秒替换为服务端下发的扫描策略；移除以进程内 `last_scan` 为唯一依据的排程判断。
- 使用单一优先队列：手动任务优先，计划任务其次；同一源合并，已运行任务不重入。
- 自动源的首次待扫、离线补扫和重试都通过领取接口获得，避免 Agent 重启立即遍历所有源。
- 保持当前的独立浏览器 Profile、登录态和分享链接行为；自动扫描需打开浏览器但不会打开新的 CLI 入库任务。
- 增加协议/行为版本。旧 Agent 不支持领取协议时，前端应显示“需升级 Agent 才能应用目录扫描频率”，不能把“仅手动”错误地交给旧版硬编码 30 分钟 Agent。

### 4. 前端交互

在 RPA 同步页完成以下 UI：

- 新建同步申请表单增加“目录扫描频率”单选/下拉项，默认仅手动；只显示五个受支持选项，不暴露 Cron 输入框。Contributor 提交的申请保持仅手动，管理员可在批准后调整频率。
- 已创建同步源增加“扫描设置”入口，仅 Admin / Owner 可见和提交。显示当前频率、最近成功完整扫描、下次预计扫描、当前扫描状态与最近安全错误。
- “仅手动”时显示“不会自动扫描”；自动源显示“下一次预计扫描”。
- “立即扫描”在排队状态显示“立即执行”，在运行状态禁用并说明扫描进行中。
- 设置保存后刷新同步源状态；不调用或登记 CLI 内容入库计划。

### 5. 兼容、部署与迁移

1. 先部署服务端迁移和兼容读取；不让旧 Agent 获得新的自动策略。
2. 发布新的 Windows Agent，并通过现有下载入口提供升级版本与版本提示。
3. 前端仅在设备版本满足协议要求时启用频率编辑；否则允许查看当前设置并提示升级。
4. 新 Agent 上线后，启用原子领取、持久状态和每源频率。
5. 回滚时保留新字段，服务端可把自动源按 30 分钟兼容处理；不得删除目录清单或已入库内容。

## 实施顺序

1. 补充领域类型、输入校验和 PostgreSQL/SQLite 迁移；为已有源写 30 分钟迁移与到期计算测试。
2. 实现服务端的扫描状态机、原子领取、完成、失败、租约恢复和权限校验；加入服务、Handler、Repository 测试。
3. 修改 Agent 队列与轮询逻辑，接入领取/结果协议；使用可注入时钟覆盖五种频率、首次扫描、离线补扫、两次失败、重启和手动提升。
4. 实现前端创建与编辑界面、状态展示和旧 Agent 升级提示；补 API 类型、组件测试与中文文案。
5. 重建并签名/发布 Windows Agent，运行端到端验收。

## 验收清单

- 新建五个测试源，分别验证仅手动、30m、1h、6h、24h 的首次与后续扫描时间。
- 重启 Agent、刷新 RPA 页面、重启服务端均不会让未到期源提前扫描。
- 计划扫描失败一次后十分钟重试；第二次失败后不高频循环。
- Agent 离线跨越到期时间后上线，每源仅补扫一次；多个源串行。
- 手动扫描能提升待执行任务，不能与运行中任务并发。
- 关闭 `auto_share` 的自动扫描不创建分享链接；开启时沿用当前受控创建逻辑。
- 更改目录扫描频率前后不新增任何 CLI 内容入库任务；“立即同步”仍是唯一的内容入库入口。
- 非 Admin / Owner 无法变更频率或触发扫描；旧 Agent 显示升级提示且不会错误应用“仅手动”。
- 运行相关 Go、Python Agent、前端类型/组件测试，执行两种数据库迁移验证和完整 Windows Agent 打包测试。
