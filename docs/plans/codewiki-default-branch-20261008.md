# 源码模式分支留空使用 GitLab 默认分支

2026-10-08 用户要求与原文档模式一致：分支可留空，并由 GitLab 识别默认分支。

## 行为

- 分支留空或仅含空白：每次预检查、新同步使用已配置 GitLab 实例的项目 API `default_branch`，再读取该分支的提交 SHA。保留空配置表达跟随默认分支的意图，不将首次解析结果写死。
- 显式填写：只使用指定分支；不存在时不回退到默认分支。空仓库或未配置默认分支会明确报错，不猜测 `main` / `master`。
- 预检查结果显示实际同步分支；分支字段取消必填标记，源码与文档共享“留空时使用默认分支”提示。
- 同步仍按固定提交执行，引用与旧版本保留语义不变。Webhook 在认证配置的 secret 后通过已保存的凭证解析默认分支，只接受该分支的推送；错误状态的默认分支源仍可参与定时修复。
- 更新 ADR-0003 和领域定义，记录用户对原“明确指定分支”规则的调整。无需数据库迁移。

## 验证

- 连接器测试覆盖省略分支、空白分支、GitLab 默认分支变化、显式分支优先、指定分支不存在、默认分支为空及带斜杠分支名称。
- 服务测试验证空分支配置保存、规则版本、原指定分支预检查及凭证轮换。
- 独立 PostgreSQL source_test 库与真实 Git、解析 HTTP 服务验证：空目录和空分支可全仓入库、搜索与源码查看；指定分支仍可发布；默认分支 Webhook 拒绝其他分支并能发布正确提交；既有推送去重及定时核对流程保持有效。
- 前端测试覆盖编辑、新建时空分支检查及保存、排除规则、就地失败和文档模式，并校验五种语言的键与语法。

- 前端 21 项测试与生产构建通过；后端连接器/服务测试与 4 项 PostgreSQL 集成测试通过，最终 Webhook 修订后另行复验两个相关集成测试。
