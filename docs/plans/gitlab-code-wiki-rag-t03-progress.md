## 范围与一致性

公开搜索和问答接受 `source_ids`，与既有租户/共享 KB、文件、标签范围取交集；同名路径和相同正文通过独立源文件及文件版本身份区分。关键词与向量在排序和 topK 截断前限制当前请求成员。未支持源码范围的外部引擎拒绝请求，不能忽略参数。

问答开始时固定各贡献源的发布快照。迁移 `000103` 将读取租约、源码范围及普通文档范围持久化；租约最长 30 分钟，有更短请求期限时采用该期限。读取上下文只携带服务端生成并验证的租约 UUID，与原始 caller 绑定。异步 RAG 输出保留租约至最后一个读者结束；取消与过期使后续读取失败。普通文档目标不会租用无关仓库，文件与标签必须由同一源码成员同时满足。

搜索、grep、代码阅读、文档信息、块分页和上下文补全使用同一快照/范围。原文 SHA-256、文件名/路径、大小和版本字段均来自固定文件版本；引用及模型上下文携带 source、snapshot、file version、commit SHA、路径和原始行号。相同文本不会跨仓库合并。暂存成员和历史问答中的旧源码命中不会进入新的当前回答。

所有读取重新检查当前 KB 权限及源是否明确清除。共享 Agent 的原始身份穿过 middleware 和派生上下文，不能换成另一 Agent 来保留已撤销权限。HTTP 首次解析资源身份只返回授权所需的所有权字段；授权后再读取正文。模型调用前、每个流片段以及 provider 关闭时检查权限，清除后不输出尾部引用或再调用综合模型。

普通文档保留原检索行为；FAQ 标签使用实际条目 `chunks.tag_id`，补全不能引入其他标签的 FAQ 条目。Git 管理的源码仍只读，标签和描述仍可管理；沿用并复验 T02 的 UI 与公开写入口。

## 后续任务必须遵守的契约

读取范围表对 snapshot 的外键使用 RESTRICT，阻止删除受保护快照。T18/T19 实现证据回收及明确清除时必须遵守租约和证据引用保护；明确清除先使读取失效，再按该任务的清理流程处理。T03 未实现回收或完整清除工作流。

源码范围向量查询先 materialize 满足完整关系范围的候选，再计算相似度及 topK。实际 pgvector 0.8.1 HNSW 全局候选预算即使开启严格迭代也会漏掉窄范围低排名成员，因此此路径优先保证范围正确。纯普通文档、无实际源码贡献的问答沿用现有 ANN 路径。源码精确扫描的成本需要在 T22 用代表仓库测量；本次 162 个混淆块的结果不证明 125 万行性能。
