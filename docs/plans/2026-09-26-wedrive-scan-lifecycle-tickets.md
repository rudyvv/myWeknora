# 微盘目录扫描生命周期：实施 tickets

对应 [Spec](2026-09-26-wedrive-scan-lifecycle-spec.md) 和 [GitHub #1](https://github.com/rudyvv/myWeknora/issues/1)。以下任务已发布到 `rudyvv/myWeknora`；发布约束见 T5。

## T1 — 集中微盘目录扫描状态转移

GitHub：[rudyvv/myWeknora#2](https://github.com/rudyvv/myWeknora/issues/2)。

**建议标题**：`[WeDrive] 建立目录扫描生命周期 module，集中状态转移与调度规则`

**目标**：形成扫描生命周期 module 的内部 seam，由现有事务入口调用。将领取、失败、超时、完整提交、频率变更的扫描字段变更集中，保持现有产品行为。

**范围**：`internal/application/service/wedrive.go` 中的扫描路径、内部 module、服务层测试；不改工具协议与前端。

**验收**：

- 从 `WeDriveService` 公开方法验证仅手动、自动到期、手动优先、同设备串行、首次失败十分钟重试、第二次按原频率等待。
- 运行中调整频率保留当前租约；完成或失败后使用新频率。无 CLI 内容入库副作用。
- 状态转移不再由多个调用方各自组合 `scan_state`、`next_scan_at`、`scan_retry_count` 和租约字段。
- 既有 PostgreSQL 并发领取测试及 SQLite 服务测试通过；不新增只镜像内部实现的 mock 测试。

**依赖**：无。**验证命令**：相关 Go service 测试，包含可用时的真实 PostgreSQL 测试。

## T2 — 领取身份与旧工具升级闸门

GitHub：[rudyvv/myWeknora#3](https://github.com/rudyvv/myWeknora/issues/3)。

**建议标题**：`[WeDrive] 为每次目录扫描领取建立持久的尝试身份`

**目标**：服务端领取返回新的 `scan_attempt_id`，来源只保留当前身份；失败报告只接受当前有效尝试。旧版工具不能继续使用无身份的扫描写入协议。

**范围**：PostgreSQL/SQLite 迁移、来源类型、领取与失败事务、Handler 协议和测试；工具客户端解析领取响应并携带身份到失败上报；前端显示新最低版本的升级提示。

**验收**：

- 两次领取产生不同身份；旧尝试的失败报告不能结束新尝试，也不能改变当前错误和下次扫描时间。
- 领取时仍保持同设备串行；来源身份、租约与 `running` 状态在同一事务写入或清除。
- 迁移将无身份的历史运行中记录转为可重试状态；手动源允许重新扫描；历史完整清单不丢失。
- `0.3.1` 等旧工具在领取和失败入口得到明确升级错误；服务端依据本次请求判断版本。前端提示升级至 `0.4.0+`，不再将旧工具显示为可扫描。新工具的领取与失败路径通过 Python 客户端测试。

**依赖**：T1。**验证命令**：迁移验证、Go service/Handler 测试、Python 客户端测试。

## T3 — 将完整清单绑定到当前扫描尝试

GitHub：[rudyvv/myWeknora#4](https://github.com/rudyvv/myWeknora/issues/4)。

**建议标题**：`[WeDrive] 阻止旧扫描清单上传与提交，并保证完成幂等`

**目标**：清单在开始时绑定尝试身份；分批上传与提交都检查该身份仍是当前有效领取。重复提交同一完整结果只返回原结果。

**范围**：两库清单迁移、`BeginSnapshot`/`UploadSnapshotItems`/`CommitSnapshot`、工具清单请求、Handler 和事务测试。

**验收**：

- 同一尝试重复开始清单返回同一上传会话；根节点或预期数量不一致返回冲突；每个尝试最多一份清单。
- 尝试超时或被新尝试取代后，旧清单不能继续上传、提交，也不能更改来源的 `last_snapshot_id`、`last_complete_scan_at` 或扫描状态。
- 相同完成请求重试只产生一次状态转移与审计；不同数量、摘要或分享统计返回冲突。
- 完整性、根节点、父子链、摘要校验仍保持；事务按来源后清单的固定顺序加锁，并由 PostgreSQL 并发测试验证。

**依赖**：T2。**验证命令**：Go service/Handler 测试、真实 PostgreSQL 并发测试、Python 客户端测试。

## T4 — 长扫描续租与服务端重启恢复

GitHub：[rudyvv/myWeknora#5](https://github.com/rudyvv/myWeknora/issues/5)。

**建议标题**：`[WeDrive] 允许有效目录扫描续租并跨服务端重启继续`

**目标**：当前尝试可以在扫描有进展时延长租约；旧尝试或过期尝试不能续租。服务端重启不直接结束仍有效的尝试。

**范围**：续租入口、生命周期 module 的超时转移、工具扫描执行循环、WebSocket 重连路径、测试。工具每 5 分钟续租；服务端以 `progress_seq` 识别真实进展，20 分钟无进展或领取后满 4 小时即结束尝试。

**验收**：

- 超过 30 分钟且符合续租条件的扫描能够提交完整清单；失去租约后工具停止后续上传/提交。
- 只有已校验的目录列表、新条目、分享操作完成或上传批次完成能推进进展序号；相同序号的重复心跳不能让无进展尝试无限存活。进展数据不含目录或凭据。
- 租约每次最多延至当前时间后 30 分钟且不得越过领取后 4 小时；20 分钟无进展或触及硬上限后释放设备扫描名额并按既有失败规则调度。
- 旧尝试续租不能延长新尝试；`now == expires_at` 判为过期。网络短暂失败可在有效期内重试，过期后不能复活。
- 服务端重启、工具重连时有效尝试保留；无心跳的尝试到期后进入既定失败/重试路径，不永久占用设备。
- 使用可控时钟和真实数据库验证超时、续租与竞争；工具测试验证心跳停止条件及失租行为。

**依赖**：T2、T3。**验证命令**：Go service/Handler/数据库测试、Python 工具测试。

## T5 — 协议发布与端到端验收

GitHub：[rudyvv/myWeknora#6](https://github.com/rudyvv/myWeknora/issues/6)。

**建议标题**：`[WeDrive] 发布扫描尝试协议并验证旧工具升级路径`

**目标**：将服务端强制校验、新工具、前端升级提示作为同一发布单元验收，避免协议切换期间出现无保护的扫描写入。

**范围**：协议版本、下载入口或安装包版本提示、Windows 构建与签名流程、发布说明和端到端验收；不提交生成的可执行文件。

**验收**：

- 旧版工具无法领取、续租、开始/上传/提交清单或上报失败，页面提示 `0.4.0+`；新版工具完整扫描通过。
- 部署迁移后不存在永久 `running` 的无身份来源；降级或回滚流程不会重新允许旧结果清算新领取。
- 人工验收手动扫描、自动到期、跨 30 分钟续租、扫描中修改频率、重启恢复及旧结果迟到；无自动 CLI 内容入库。
- 相关 Go、Python、前端检查及 PostgreSQL/SQLite 迁移验证通过；Windows 工具产物重新生成。2026-09-27 项目负责人确认当前内部使用暂不要求代码签名，允许显式发布未签名包，保留签名构建路径。

**依赖**：T1–T4。**发布约束**：T2–T4 的代码可以分项评审，但强制新协议与新工具需要同批交付。
