# ADR-0001：采用 RPA 目录发现与 CLI 内容拉取的企业微信微盘同步架构

- 状态：Accepted
- 日期：2026-09-17

## 背景

企业微信微盘 API 无法完整读取企业既有的人工创建空间，`wecom-cli` 能按已知引用读取或下载内容，却不能从指定目录递归枚举全部子项。单独使用任一通道都无法持续构建可信且可消费的知识库数据源。

项目负责人拥有目标项目目录的可见性，企业资料管理员维护统一的 CLI 内容拉取身份。系统还需要避免在负责人电脑或服务端长期保存全量文件，并沿用 WeKnora 现有的数据源、解析与入库链路。

## 决策

采用混合架构：Windows RPA Sync Agent 负责目录发现与受控的离线文件分享；WeKnora 服务端负责审批、清单差异、任务编排与审计；独立 WeCom Fetch Worker 使用租户级 CLI 连接逐项拉取内容并流式交给知识库入库。

具体边界如下：

- 一个已批准同步源绑定一个微盘根目录、一个知识库、一个 CLI 连接，并租用一台已注册设备扫描。
- Agent 通过出站 TLS WebSocket 接收固定协议任务，使用独立浏览器 Profile；企业微信登录态不上传。
- 清单通过分批快照协议原子提交，只有完整快照参与差异与删除计算。
- 自动分享默认开启但仅作用于批准根目录内受支持的离线文件；在线文档成员权限由企业管理员治理。
- CLI 凭据属于租户级连接，知识库数据源只保存连接引用。Web 主服务不执行 CLI，只有专用 Worker 在任务执行时解密凭据。
- 内容逐项临时落盘、解析、入库并清理；不得把整个微盘目录镜像到本机或服务器。
- 系统信任受管终端与签名 Agent，不宣称抵御恶意本机管理员篡改 RPA。

## 后果

### 正面

- 可以覆盖人工创建的既有微盘空间，同时集中治理知识库入库和 CLI 凭据。
- 负责人电脑只维护目录元数据和浏览器会话，不保存全量项目文件。
- CLI 连接可在租户内复用并统一轮换，数据源继续复用 WeKnora 的同步与解析基础设施。
- 完整快照、删除宽限和显式不可消费状态降低误删与假成功风险。

### 代价

- 必须安装并维护 Windows Agent、浏览器兼容版本及设备注册协议。
- RPA 会受企业微信页面变化、交互式验证、锁屏和客户端策略影响，无法承诺严格实时。
- 需要新增租户级连接、设备、申请、快照和条目状态模型，以及独立 Worker 部署单元。
- 目录真实性最终依赖受管终端信任；需要更强对抗能力时必须更换枚举通道。

## 被否决的方案

- 仅使用微盘 API：不能覆盖人工创建的既有空间。
- 仅使用 `wecom-cli`：无法从目标目录递归构建目录树。
- 负责人电脑下载后上传：占用终端磁盘和带宽，分散凭据、重试与审计治理。
- 将 RPA 直接运行在 WeKnora 服务端：服务端没有负责人交互式登录态，也无法可靠承载每位负责人的桌面会话。
- 把 BotID / Secret 复制进每个知识库：造成凭据重复、轮换漂移和扩大暴露面。
