# ADR-0003：GitLab 源码知识采用指定分支快照与知识库访问边界

- 状态：Accepted（Q38 已确认整体方案）
- 日期：2026-09-28

WeKnora 在保留原有文档接入与处理能力的基础上，增加 GitLab 源码增量同步、可追溯的技术 WikiPage 和源码关键词及向量检索。2026-09-28 的设计访谈确认以下产品与治理边界，以限制首期复杂度并复用现有知识库访问模型。

- 首期每个仓库跟踪一条分支的最新成功快照，所有代码引用固定到提交 SHA；多分支及历史版本检索留待后续扩展。2026-10-08 用户调整接入规则：分支可留空，每次预检查或新同步从 GitLab 项目信息解析默认分支，再解析并固定提交；显式填写则保持指定分支。解析失败不猜测 main/master，不替换已有发布版本。
- 技术 WikiPage 按系统、模块与业务流程组织，关联关键符号及代码证据；函数级定位主要由源码检索承担，不要求为每个文件或函数生成页面。
- 一个代码同步源绑定一个仓库、一条显式指定或按 GitLab 默认配置解析的分支与一个目标知识库；同一知识库可以同时接入多个代码同步源、技术 WikiPage 及原有文档。内容保留仓库命名空间，检索支持限定仓库。
- 已接入源码及卡片的阅读权限以目标知识库为准，由管理员控制接入与分享，不在每次阅读时检查用户的 GitLab 仓库权限。GitLab 中单个用户权限的撤销不会自动撤销其既有知识库访问权，因此管理员必须把知识库分享范围作为源码授权范围管理。
- 目标 GitLab 为内网自建，WeKnora 服务端可以直接访问；允许服务端保留仓库副本，并将源码发送给现有生成模型和 Embedding 模型。接入使用只读身份。

相较同时支持多分支历史查询及实时 GitLab 用户权限校验，此范围降低版本选择、身份映射和权限同步的复杂度；代价是首期不提供历史版本检索，且内容授权由知识库治理承担。首批语言与规模、更新触发、Agent 模式、Tree-sitter 选型与增量影响规则见设计访谈记录，源码与 Wiki 发布关系见 ADR-0004，静态分析范围见 ADR-0005，Git 获取方式见 ADR-0006，历史证据保留见 ADR-0007，源码写入及整页读取边界见 ADR-0009；具体执行与持久化建议见已由 Q38 确认的 [整体方案](../plans/gitlab-code-wiki-rag-implementation-plan.md)。依赖与性能仍需实施验收。
