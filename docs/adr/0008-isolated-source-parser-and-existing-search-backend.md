# ADR-0008：独立源码解析服务与既有 PostgreSQL 检索后端

- 状态：Accepted（Q26、Q29、Q30，具体依赖与接口待实现方案及验收）
- 日期：2026-09-28

代表仓库约有 125 万行自有文本，源码结构、位置和错误恢复不能由现有 Markdown 读取接口可靠表达。首期采用独立 Python 服务复用 Tree-sitter 成品解析与分块，并用固定版本官方 Node 组件解析 Vue SFC；Go 负责同步、权限、快照及索引发布，结构化结果直接进入源码加工。相较将原生解析嵌入应用或挤入普通文档线程池，这增加一个部署组件，但可隔离解析故障和资源峰值；Lite 可连接同一外部服务。

Vue SFC 的预处理质量按顶层块类型和 `lang` 共同判定；未支持的组合保留原始字节并标记 `unknown_preprocess`，不执行仓库提供的插件或预处理器。描述符告警只携带受控代码和原文 UTF-8 范围进入受影响块的来源证据；面向模型的说明由受限静态文案生成，不传播解析器错误文本。

检索首期复用现有 PostgreSQL/ParadeDB 双索引并适配代码标识符、仓库与已发布快照范围，避免同时引入新搜索基础设施。代价是其他后端需后续逐步完成源码能力验收；首期的范围正确性不能靠召回后过滤或现存 Chunk metadata 推断。库的成品能力、运行性能及精确坐标尚需在实现阶段验证，此决定不是对解析速度或召回效果的实测承诺。
