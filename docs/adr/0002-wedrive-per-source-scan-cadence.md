# ADR-0002：微盘目录扫描频率独立于内容入库调度

- 状态：Accepted
- 日期：2026-09-22

## 背景

微盘同步源同时包含两个不同的持续性行为：Windows RPA Agent 发现并提交目录清单，以及服务端内容拉取 Worker 使用 CLI 将已知条目入库。两者的权限、资源消耗、失败模式和操作者均不同。现有 `sync_schedule` 代表数据源的内容入库计划，而 Agent 将目录扫描频率硬编码为 30 分钟且只保存在进程内；复用同一个字段会使“只更新目录”意外变成“下载并解析内容”，也会在 Agent 重启时丢失调度状态。

## 决策

为每个微盘同步源维护独立、持久化的目录扫描频率和扫描调度状态，不复用数据源的 CLI 内容入库计划。频率只能是仅手动、30 分钟、1 小时、6 小时或每天；仅 Admin / Owner 可以修改。自动源批准后建立首份清单，后续以最近一次成功完整扫描为基准；离线恢复时每源至多补扫一次，同一设备串行扫描。失败后十分钟重试一次，第二次失败后回到原频率。自动扫描严格遵循同步源已有的分享链接授权开关，手动扫描优先于等待中的计划扫描但不得并发。

现有同步源迁移为每 30 分钟，以保持既有目录扫描行为；新申请默认仅手动。CLI 内容入库保持手动触发，微盘数据源不登记内容入库 Cron，迁移时清除已有微盘数据源的误登记计划。

## 被否决的方案

- 复用 `sync_schedule`：会混淆目录事实更新与内容下载、解析、向量化，且可能产生意外的 CLI 调用。
- 只在 Agent 内存保存上次扫描时间：重启后会立即重复扫描，页面也无法准确显示下次时间或重试状态。
- 允许任意 Cron 文本：增加误配置和跨时区理解成本，当前产品只需要五种经过治理的频率。

## 后果

需要增加同步源调度状态、Agent 与服务端之间的领取/结果协议、管理员设置界面以及旧 Agent 的升级提示。代价换来每源可预测的目录更新、可审计的状态和不触发内容入库的频率调整。
